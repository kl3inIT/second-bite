# SEC-208 — Change the password of an account made with a username: design

Tracked in Linear as SEC-208. Asked for on 21 November 2026 by the person who runs the web, after phones with a Vietnamese keyboard added marks to the passwords typed on the sign-in screen (`laparis123` became `lâpris123`) and the accounts made for the pilot's stores could not be opened. This increment builds the API and the web; the app follows in its own issue. It adds to [SEC-193](../sec-193-username-sign-in/design.md), whose rules for a username and a password it keeps.

## 1. What changes for a person

- An account made with a username has a **Change password** form on its account screen: the password it has now, the new password, the new password again.
- Typing the old password is the only proof asked. No email and no code: the account has no address (SEC-193, section 2).
- When it works, the person stays signed in on this device; every other device is signed out.

## 2. Rules

- **New password:** the rules of SEC-193, section 3 (8 to 128 characters, not the username). It may equal the old one; refusing that adds a rule and protects nothing.
- **Wrong old password:** `IDENTITY_PASSWORD_INCORRECT`, counted with the username's wrong tries to sign in (5 in 15 minutes, then `IDENTITY_SIGN_IN_LIMIT_EXCEEDED` without comparing). A stolen session cannot be used to guess the password beyond that bound; the count is the one deleting the account already uses.
- **Order of the checks:** the new password's form first (it costs nothing and spends no try), then the old password.
- **Other sessions end** in the same transaction as the new hash, so a thief's session does not outlive the change. The session making the request stays.
- **Accounts without a password** (emailed code, Google) are refused with `IDENTITY_NO_PASSWORD`. The web does not show them the form. Giving them a password is not part of this.

**Not chosen:**

- **Asking for an emailed code:** the accounts this is for have no address.
- **Ending every session, this one included:** the person would have to sign in at once with the password they just typed, on the keyboard that mangled it before.
- **An admin resetting a password:** it needs its own audit design (SEC-193, section 6). Forgetting the password stays unrecoverable.

## 3. Interface

| Operation | Who | Answer |
| --- | --- | --- |
| `PUT /accounts/me/password` `{currentPassword, newPassword}` | A signed-in caller whose account has a password | `204`; the hash is replaced and the account's other sessions end |

Failures, all existing: `IDENTITY_PASSWORD_INVALID` (400, the new password), `IDENTITY_PASSWORD_INCORRECT` (400, the old one), `IDENTITY_SIGN_IN_LIMIT_EXCEEDED` (429), `IDENTITY_NO_PASSWORD` (409). `api/openapi.yaml` is regenerated by the backend.

## 4. Data

No migration: `identity_accounts.password_hash` is replaced in place; `identity_sessions` rows of the account but the current one are deleted. The password is never logged and never in an error. The log line records the account and that its password changed, as an event `identity.password.changed`.

## 5. Web

A card on the account screen of an account that has a username: three password fields (`autocomplete` `current-password`, `new-password`, `new-password`), one button, the same errors as the register form for the new password, and the field of the old password marked wrong on `IDENTITY_PASSWORD_INCORRECT`. Strings in both catalogs. A short hint under the new password says to switch the phone's keyboard to English before typing it, which is why this exists.

## Verification plan

- **Go (`TestService`, run by CI):** the password changes and the new one signs in while the old one is refused; a wrong old password is refused and counted, and the sixth try in the window is refused even with the right one; a new password that is too short or is the username is refused before a try is spent; the other sessions of the account end and the current one lives; an account without a password is refused.
- **Web:** Playwright with axe on the card at 390 and 1440, against the stub backend; CI runs the suite, it is not run on a developer's machine.
- **Against the real service:** change a pilot account's password, sign in with the new one.
